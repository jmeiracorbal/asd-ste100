# ASD-STE100 transformation examples

These examples show the intended behavior of the skill. They demonstrate style and structure. They do not prove formal ASD-STE100 compliance.

## Procedure

Before:

`The component should then be carefully installed into the housing after making sure that the connector has been disconnected.`

After:

`Make sure that the connector is disconnected.`

`Install the component in the housing.`

Why:

- The condition comes before the action.
- The instruction uses direct imperative language.
- The passive construction and unnecessary adverbs are removed.

## Description

Before:

`The service is responsible for performing the processing of the requests that are received from the API gateway.`

After:

`The service processes requests from the API gateway.`

Why:

- The sentence uses active voice.
- The nominalized phrase is replaced with a direct verb.
- The technical meaning is unchanged.

## Consistent terminology

Before:

`Start the application. When the program is running, check whether the service has created the database connection.`

After:

`Start the application.`

`When the application runs, make sure that the service creates the database connection.`

Why:

- `application` is used consistently for the same concept.
- The text does not alternate between `application` and `program` only for style.

## Explicit condition

Before:

`Restart the pod when the health check continues to fail.`

After:

`If the health check continues to fail, restart the pod.`

Why:

- The reader knows the condition before the required action.

## Software documentation

Before:

`In order to be able to retrieve the dataset, the client will need to provide an identifier which has previously been generated by the system.`

After:

`To get the dataset, the client must supply the dataset identifier.`

Why:

- The sentence removes unnecessary wording.
- `dataset identifier` is an explicit technical noun.
- The required action is clear.

## Non-English output

If the user asks for Spanish text in an ASD-STE100 style, apply the same clarity principles but do not call the result formally compliant with ASD-STE100.

Example:

Before:

`En el caso de que el pod deje de funcionar de manera inesperada, Kubernetes intentará proceder nuevamente a su creación siempre que la política configurada permita llevar a cabo dicha operación.`

STE-inspired Spanish:

`Si el pod se detiene de forma inesperada, Kubernetes puede iniciarlo otra vez.`

`La política de reinicio controla esta acción.`
